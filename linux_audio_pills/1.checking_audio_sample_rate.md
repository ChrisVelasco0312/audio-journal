# Checking the Current Audio Sample Rate on Linux (Ubuntu)

When working with audio on Linux, knowing your system's current sample rate is essential. Mismatched sample rates between your application and the audio server cause resampling, which introduces latency and potential quality degradation. This note covers the tools and commands to inspect your audio configuration.

## The Audio Stack on Modern Ubuntu

Ubuntu (22.04+) defaults to **PipeWire** as the audio server, replacing PulseAudio and JACK. PipeWire handles all audio routing, mixing, and device management. Understanding which server you are running determines which commands work.

Check which audio server is active:

```bash
systemctl --user status pipewire pulse
```

If PulseAudio is not installed (common on fresh Ubuntu installs), `pactl` commands will fail with "command not found". PipeWire provides its own set of tools.

## Checking the Sample Rate

### Method 1: PipeWire Metadata (Most Reliable)

The PipeWire settings server stores the active configuration in a metadata node. This is the definitive source for the current running sample rate.

```bash
pw-metadata -n settings
```

**How to read the output:**

```
Found "settings" metadata 31
update: id:0 key:'clock.rate' value:'48000' type:''
update: id:0 key:'clock.allowed-rates' value:'[ 48000 ]' type:''
update: id:0 key:'clock.quantum' value:'1024' type:''
update: id:0 key:'clock.min-quantum' value:'32' type:''
update: id:0 key:'clock.max-quantum' value:'2048' type:''
update: id:0 key:'clock.force-quantum' value:'0' type:''
update: id:0 key:'clock.force-rate' value:'0' type:''
```

Field by field:

- **clock.rate**: The global sample rate in Hz. This is the master clock rate that PipeWire uses for all nodes unless overridden. In this case, 48000 Hz (48 kHz).
- **clock.allowed-rates**: The list of sample rates the server is permitted to use. When set to a single value like `[ 48000 ]`, the server is locked to that rate and will not auto-negotiate with clients requesting a different rate. If multiple rates are listed (e.g., `[ 44100 48000 96000 ]`), PipeWire can switch dynamically depending on what the active client requests.
- **clock.quantum**: The default buffer size in frames. At 48000 Hz with a quantum of 1024, each processing cycle handles 1024 frames, which equals approximately 21.3 ms of audio (1024 / 48000 = 0.0213 seconds).
- **clock.min-quantum** / **clock.max-quantum**: The allowed range for buffer size. PipeWire can adjust the quantum dynamically within these bounds to accommodate low-latency or high-throughput demands.
- **clock.force-quantum**: When set to 0, the quantum is not overridden. A non-zero value forces a specific buffer size regardless of client requests.
- **clock.force-rate**: Same as above but for sample rate. A value of 0 means no forced override.

### Method 2: PipeWire Node Dump

```bash
pw-dump
```

This outputs the full PipeWire graph as JSON. It lists every node (source, sink, filter, driver) with its properties. Parse it to see per-node configuration:

```bash
pw-dump | python3 -c "
import json, sys
data = json.load(sys.stdin)
for node in data:
    info = node.get('info', {})
    props = info.get('props', {})
    if 'node.name' in props:
        name = props.get('node.name', 'unknown')
        rate = props.get('audio.rate', 'N/A')
        ch = props.get('audio.channels', 'N/A')
        fmt = props.get('audio.format', 'N/A')
        print(f'{name}: rate={rate}Hz channels={ch} format={fmt}')
"
```

The `audio.rate` property on individual nodes shows the rate negotiated for that specific node. If your DAW or plugin requests 96000 Hz but the server is locked to 48000, the node may report 48000 because PipeWire resamples at the graph level.

### Method 3: PipeWire Node List (Quick)

```bash
pw-cli ls Node
```

Outputs node names and properties in a human-readable format. Less structured than `pw-dump` but faster for a quick glance. Look for lines containing `sample-rate` or `audio.rate`.

### Method 4: ALSA Hardware Parameters

```bash
cat /proc/asound/card1/pcm0p/sub0/hw_params
```

Replace `card1` with your sound card number. This reads directly from the ALSA kernel interface and shows the actual hardware parameters of the open device. If the output says `closed`, the device is not currently in use by any application.

**How to find your card number:**

```bash
aplay -l
```

This lists all ALSA playback devices. Each card is numbered. The Scarlett 2i2, for example, appears as `card 1`. The HDMI outputs from NVIDIA appear as `card 0`.

The `hw_params` output (when the device is active) looks like:

```
access: RW_INTERLEAVED
format: S32_LE
subformat: STD_LE
channels: 2
rate: 48000
```

This confirms the hardware is running at 48000 Hz with 2 channels and 32-bit signed little-endian format.

### Method 5: PulseAudio (Legacy)

If PulseAudio is installed (or PipeWire's PulseAudio compatibility layer is active):

```bash
pactl info | grep "Sample Specification"
pactl list sinks | grep "Sample Rate"
```

These query the PulseAudio server through its native protocol. On PipeWire-only systems, `pactl` is typically not available, and these commands will fail.

## Default Configuration File

The default sample rate is set in the PipeWire system configuration:

```bash
cat /usr/share/pipewire/pipewire.conf | grep "default.clock.rate"
```

This shows the compiled default (usually 48000 Hz). User overrides go in `~/.config/pipewire/pipewire.conf` or files under `~/.config/pipewire/pipewire.conf.d/`. If no user override exists, the system default applies.

## Common Sample Rates

| Rate | Context |
|------|---------|
| 44100 Hz | CD quality, music production standard |
| 48000 Hz | Video production, broadcast, default on most Linux systems |
| 88200 Hz | High-resolution audio (2x CD) |
| 96000 Hz | High-resolution audio, professional recording |
| 176400 Hz | Ultra high-resolution (4x CD) |
| 192000 Hz | Ultra high-resolution, specialized recording |

## Summary of Commands

| Command | Purpose |
|---------|---------|
| `pw-metadata -n settings` | Active PipeWire clock rate and buffer settings |
| `pw-dump` | Full PipeWire graph as JSON, per-node properties |
| `pw-cli ls Node` | Quick list of PipeWire nodes |
| `aplay -l` | List ALSA sound cards and devices |
| `cat /proc/asound/cardX/pcmYp/subZ/hw_params` | ALSA hardware parameters for a specific device |
| `pactl info` | PulseAudio server info (if available) |
| `pactl list sinks` | PulseAudio sink details (if available) |
| `systemctl --user status pipewire` | Check if PipeWire is running |
| `cat /usr/share/pipewire/pipewire.conf` | System default PipeWire configuration |
