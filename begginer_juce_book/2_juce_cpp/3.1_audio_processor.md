## Audio procesor

plugin consist of

`DelayAudioProcessorEditor` handles user interface

`DelayAudioProcessor` main object of plugin
handles communication with host
and process the audio

The code for `DelayAudioProcessor` lives in two files
`PluginProcessor.h`
```cpp
class DelayAudioProcessor : public juce::AudioProcessor
{
public:
//=========================================================================
	DelayAudioProcessor();
	~DelayAudioProcessor() override;

//=========================================================================void 

	prepareToPlay (double sampleRate, int samplesPerBlock) override;
	void releaseResources() override;

	#ifndef JucePlugin_PreferredChannelConfigurations
	bool isBusesLayoutSupported (const BusesLayout& layouts) const override;
	#endif
	
	void processBlock (juce::AudioBuffer<float>&, juce::MidiBuffer&) override;
	// ...other functions omitted...
	private:
	//=========================================================================
	JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR (DelayAudioProcessor)
};
```

The **.h** or **header file** tells compiler that plug-in
has an object named `DelayAudioProcessor`.

the definition of an object is
```cpp
class DelayAudioProcessor : public juce::AudioProcessor {};
```

first line gives a name to a new class 
that inherits from another existent class `juce::AudioProcesor`

`juce::AudioProcesor` is provided by JUCE
knows everything about how to communicate with host.
Inheriting from this, we don't have to write all the host communication.

`public:` 
An object has public and private pars.
All following `public:` is visible to other objects
everythis after `private:` can only be used by `DelayAudioProcessor`

### functions or methods
`DelayAudioProcessor();`
A function with the same name as the object is **constructor**
When the host loads the plgu-in in memory
it does using the constructor.

`~DelayAudioProcessor() override;`
This is the **destructor**
if user removes plug-in from track
host unloads form computer memory calling destructor

`void prepareToPlay(double sampleRate, int samplesPerBlock) override;`
Host calls `prepareToPlay` when wants to start playing audio
Gives plug-in the opportunity to get ready
Delay plguin will use this method to reserve enough free space
in computer's memory to store up to 4 seconds of stereo sound

The function has 2 arguments
**sample rate** and **maximum block size**
Audio is processed in groupes known as blocks
`samplesPerBlock` host tells plug-in how large a block size to expect.

`void releaseResources() override;`
is counterpartto `prepareToPlay`
is called when the host stopped playing audio
is used to let the plug-in free any resources no longer needs.

```cpp
#ifndef JucePlugin_PreferredChannelConfigurations
 bool isBusesLayoutSupported (const BusesLayout& layouts) const override;
#endif
```

host transport audio data to and from the plug-in over a **bus**
refers to how audio is routed between different parts of the mixing console
`isBusesLayoutSupported` negotiates with host 
whether the buses used will be mono, stereo, or have more channels

> `#ifndef` and `#endif` directives
> will disable `isBusesLayoutSupported` if 
> an option in Projucer named Plugin Channel Configurations is used.

#### the most important function
`void processBlock (juce::AudioBuffer<float>&, juce::MidiBuffer&) override;`
This is where **DSP** happens
Is where audio processing code is located

Host calls `processBlock` function hundred or thousands of times per second

`void getStateInformation (juce::MemoryBlock& destData) override;`
`void setStateInformation (const void* data, int sizeInBytes) override;`
This are used by host to save and restore plug-in's parameter values
This allows the user to sabe their DAW session and load it again at a later time

### `PluginProcessor.cpp`

header file tells compiler which functions are in the `DelayAudioProcessor`
but not what they do. `PluginProcessor.cpp` contains the logic code for this.
