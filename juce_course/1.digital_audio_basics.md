# What is sound?

- propagation of air pressure changes in the air.
- number of full oscillations per second -> Frequency in HZ hertz
- human hearing range: 20-20 000hz

## how to represent the sound on a computer?

We as developers work with random access memory (ram).
We use a microphone to transform the acoustic sound signal into digital form. 
The microphone convert air pressure changes to voltage changes.

To represent voltage changes in computer we use **SAMPLING**

## Sampling

Record the voltage value at regular time intervals and store it on memory.
Evenly spaced discrete values

The **time interval** between the samples is the **sampling period**. 

Sampling rate is often written as $fs$, tells us the speed or frequency of our clock. Measures how many individual measurements the system takes in a single second.
	- Standard CD-quality audio uses a sampling rate of 44100 Hz (Hertz): The system capture 44100 individual snapshots of the sound wave.
	- Video production frequency uses 48000 Hz (48 kHz)

**The sampling period**
It is the reciprocal of the **sampling rate** $f_s$ which is the number of samples we get per second.

In maths, a **reciprocal** is what you get when you divide 1 by a number.
Represents an inverse relationship: As one value goes up, the other must go down.

$$
T = \frac{1}{fs}
$$
They are inverses, knowing one gives you the another:
	- **High sampling rate** = **Short Sampling Period**: Taking a massive number of samples per second, shortens the gap between each sample.
	- **Low Sampling Rate = Long Sampling period**: Fewer samples per second means the time gap between them becomes wider.

$$
fs = \frac{1}{Ts}
$$

The process of transforming an analog signal into a series of samples is called, **Analog-to-digital (A/D) conversion**, the electronic unit is **ADC**.

Then to obtain an analog signal from discrete samples we need Digital-to-Analog (D/A) conversion. The electronic unit that performs the conversion is **DAC**

## Sound playback

A sound signal converted into voltage can be amplified and played back via a **speaker** that transforms the **analog signal** into an **acoustic wave.**

Every audio interface contains an ADC and a DAC. It can be recognized by seeing analog inputs, analog outputs, and a digital USB connection to the computer.

## Floating point sample representation

In audio plugin processing, a single sample is a **floating-point** value in the `[-1, 1]`  range. 
If a sample exceeds this range at the output, it will clip. We see a red indicator on the DAW's level meters.
![[floating_point_sample.png]]
In C++ a sample is represented by the `float` type or the `double` type.

These samples are stored in simple arrays.
An array of samples is a **mono** signal; A signal that contains just a single **channel** of samples.

Most audio setups have more than one loudspeaker.
The stereo setup with two channels is probably the most popular.

The pure notion of a sample is not enough to specify the complete audio content at a single instant because one sample is present only on a single channel.

We need a name for a collection of samples from all channels at a single point in time.

## A frame

It is a collection of samples from several channels at a single point in time.
If we process a mono signal, a frame contains just one sample.
If we process a stereo signal, a frame contains two samples and so on.

![[frame.png]]


In all audio plugins and apps, audio is processed in **blocks**

## Sample block/buffer

A block or a buffer is a collection of successive frames. 
The number of frames in a buffer is called the **buffer size** 
A buffer contains an array of audio samples for each channel it represents.

Since the sample rate is known and the number of frames 
in a block is fixed for a particular block.
This collection of frames has a known length in seconds.

If our plugin operates at the sampling rate of 48000HZ 
and the number of frames in a buffer is equal to 480,
this buffer represents $480/48000$ so 0.01 seconds.
In other words, it represents 10 milliseconds.

The number of frames in a buffer divided by the sampling rate
always conveys the length of the buffer in seconds, regardless of the channel count.

The number of frames in a buffer equals the number 
of samples of a single channel of this buffer.

A frame contains a single sample per channel at a single instant.
